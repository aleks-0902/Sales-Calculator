# Sales Studio 多商品销售分析

在原有项目上升级，核心仍为 `index.html`、`style.css`、`script.js`，不依赖框架或联网服务。

## 打开与使用

双击 `index.html`，使用 Edge 或 Chrome 打开。若已经打开旧版，刷新页面。

初始列表包含 MacBook（售价 8000、成本 6200、数量 12）。左侧输入商品信息，点击“添加到商品列表”或按 Enter，即可加入列表。成功后表单清空，方便继续录入。相同名称可重复添加，每条记录可独立删除。“重置输入”仅恢复表单默认值，保留列表。

添加和删除后自动更新销售额、总成本、总利润及整体利润率。商品列表自动保存在此浏览器的 localStorage 中。添加或删除后自动保存，刷新后恢复；首次使用默认 MacBook，删除全部商品后刷新仍保持空列表。存储不可用时会显示警告。

## 计算与校验

- 商品销售额 = 售价 × 数量；商品总成本 = 单件成本 × 数量。
- 商品利润 = 商品销售额 − 商品总成本。
- 单品利润率 = 商品利润 ÷ 商品销售额 × 100%。
- 汇总金额为所有记录的相应金额之和。整体利润率 = 总利润 ÷ 总销售额 × 100%，不是单品利润率的简单平均。
- 商品名称不能为空或仅含空格；金额必须非负且最多两位小数；数量必须为非负整数。空值、非数字和超出安全范围的数据不能添加。
- 销售额为零时利润率显示“—”；亏损以红色显示；空列表显示引导提示。
- 未提交或无效的输入不会改变已添加数据。未计入税费、运费等其他支出。

## 利润率质量提示

整体利润率卡片和每条商品的利润率单元格均增加标签：未四舍五入的利润率达到或超过 20% 显示绿色 `Good Profit Margin`；低于 20%（含亏损）显示橙色 `Low Profit Margin`。零销售额或空列表显示“—”与中性的“利润率不适用”。

测试门槛时先删除现有商品，再分别添加售价 100、数量 1、成本 80 / 80.01 / 79.99 的商品，预期利润率为 20.00%（绿色）/ 19.99%（橙色）/ 20.01%（绿色）。整体标签根据全部已添加商品计算，不能只看最新商品。

本次代码职责：
- `index.html` 的 `margin-rating`：为整体利润率标签提供显示位置，保留既有布局。
- `style.css` 的 `.margin-rating` 及三个颜色类：定义标签布局和绿色、橙色、中性外观。
- `script.js` 的 `safePercent`：仅在分子、分母为有限数字且分母大于零时计算比例；无效结果返回 null。
- `percent`：将有限比例格式化为两位小数，其余显示“—”。
- `showMarginRating`：统一设置提示文字和颜色类，使用原始比例比较 20% 门槛。
- `render`：为单品创建标签并更新整体标签，添加删除后都会重新计算。
- `parseCents`：从金额字符串精确解析整数分，避免超大金额先转浮点数造成分位丢失；超出安全范围则拒绝。
- `readProduct`：保留金额原始字符串，并先检查数量为纯整数字符串，避免超大数量的小数被舍入后误通过。
- `verify.cjs`：新增利润率门槛、颜色类、无效数字、零销售额和大数解析的回归检查。模拟 DOM 的按钮查询已排除新增标签元素。

## localStorage 自动保存

继续使用同一浏览器和同一网页地址。此功能保存的是已添加的商品列表，不保存尚未提交的表单输入；“重置输入”不会清空商品存档。

### 实现说明

- `STORAGE_KEY`：固定存储键 `salesStudioProducts`，只操作本项目这一项，不清空其他网站数据。
- `saveProducts()`：把名称、售价分、成本分、数量包装为 `{ version: 1, products: [...] }`，通过 `JSON.stringify` 保存。添加和删除均调用；失败时保留当前内存列表并提示，下次操作会重试。
- `restoreProducts(raw)`：解析 JSON，检查版本、列表结构、名称、非负安全整数、单品及累计数值范围。重新计算收入、成本、利润，并重新分配 ID。任何记录不合法都拒绝整份存档，避免静默丢掉部分商品。
- `loadProducts()`：没有存档（getItem 返回 null）时创建并保存默认商品；合法空列表按空列表恢复；读取失败或存档损坏时临时使用默认商品并显示警告。损坏数据不在加载时覆盖，下次成功添加或删除才用当前列表替换。
- `nextId`：恢复后从列表长度加一开始，避免新商品与恢复商品 ID 重复。
- `storageMessage()`：在明细区域显示保存、恢复或失败状态，通过 role=status 支持辅助阅读工具。
- 存储采用版本号，方便以后升级格式；版本不支持时走损坏数据提示。

### 测试步骤

1. 首次使用：没有本项目存档时打开页面，应显示默认 MacBook，并提示已自动保存。
2. 添加 Mouse（100 / 60 / 10），刷新，确认两条商品和汇总均保留。
3. 删除其中一条，刷新，确认删除结果保留。
4. 删除全部商品，再刷新，应保持空列表，不能重新出现 MacBook。
5. 从空列表添加新商品，刷新后再次添加、分别删除，确认每条可单独操作。
6. 在表单输入无效数据并尝试添加，刷新，已有商品应不受影响。
7. 测试损坏存档（仅在测试数据上操作）：在浏览器开发者工具的 Application / Storage / Local Storage 中找到 `salesStudioProducts`，把值改成 `broken` 并刷新。应显示警告和默认商品。修改为合法 JSON 但含负数成本、缺少字段或错误版本，也应拒绝。下一次成功添加或删除会替换损坏存档。
8. 测试存储失败：在浏览器限制此页存储访问，重新打开并尝试添加或删除。页面应继续计算并显示警告。不同浏览器的设置方式不同；自动测试已模拟读权限拒绝和写入空间不足。

重新测试“首次使用”时，仅删除 `salesStudioProducts` 这一项即可；这会删除本项目在当前浏览器中的已保存列表。不要使用 localStorage.clear() 清空其他应用数据。

`node verify.cjs` 已覆盖首次使用、模拟刷新、添加删除持久化、空列表、ID 唯一、数据损坏及无效字段、单品和累计溢出、重算结果、读取失败、写入失败及重试。真实浏览器存储权限与 file:// 地址下的兼容性仍需按以上步骤实测。数据只属于当前浏览器，不会同步到其他设备；多个页面同时编辑时，最后一次成功保存的列表为准。

## 商品盈利排行榜与编辑

明细表下方新增排行榜，展示名次、商品名称、总利润和利润率。按每条记录的总利润（售价减成本，再乘数量）降序；利润相同时保持明细表顺序。同名商品仍分别排名。亏损商品正常参与排名，零销售额利润率显示“—”。

明细表的“修改”按钮将商品信息回填左侧表单，点击“保存修改”后原位替换该记录，保留 ID 和顺序，自动更新汇总、排行榜和存档。“取消修改”不改变原数据；“重置输入”退出修改并恢复默认输入。删除正在修改的商品会退出修改状态，避免误保存。未提交的编辑内容不写入存档。

### 代码职责

- `editingId`、`startEditing()`、`finishEditing()`：管理添加和修改模式，以及表单回填和取消。
- `readProduct()`：编辑时从累计校验中排除旧记录，检查替换后的总额，而不是将新旧两条重复计入。
- 表单提交事件：添加时生成新 ID，编辑时原位替换并保留 ID；完成后重新渲染和保存。
- `rankProducts()`：先校验原始数据并重算利润，再对新数组排序。利润相同时比较原始下标，保持明细表顺序；不修改 `products` 数组。
- `renderRanking()`：用 textContent 生成排行榜行，避免名称 HTML 注入；无数据时显示空状态，无效记录被跳过并提示。
- `render()`：统一调用排行榜渲染，保证添加、删除、保存修改及页面恢复后同步。

### JavaScript sort() 与 Python sorted()

| 特性 | JavaScript Array.sort() | Python sorted() |
| --- | --- | --- |
| 原数据 | 原地修改数组，返回该数组 | 返回新的列表，原可迭代对象不变 |
| 默认规则 | 将元素转为字符串比较；数字排序需提供比较函数 | 按对象的默认顺序比较；数字按数值排序 |
| 自定义 | 比较函数返回负数、零、正数 | 通常使用 key 提取排序字段，reverse=True 降序 |
| 输入 | 数组方法 | 可接收列表、元组等可迭代对象 |
| 同值顺序 | 现代 JavaScript 标准保证稳定排序 | 保证稳定排序 |

JavaScript 示例：`const ranked = [...products].sort((a, b) => b.profitCents - a.profitCents);`

Python 示例：`ranked = sorted(products, key=lambda item: item["profitCents"], reverse=True)`

两者都按利润降序。JavaScript 先复制数组再 sort，才能保留原明细顺序。本项目还显式用原下标打破同利润的平局。Python 中与 JavaScript 原地 sort 更接近的是 list.sort()，它原地修改列表并返回 None。

## Business Insights（商业洞察）

盈利排行榜下方新增商业洞察，保留现有页面和文件结构。模块使用当前已添加的记录，不将未提交的表单内容视为商品更改。所有建议均为固定规则生成，无 AI 模型调用。

### 三个新增函数

- `calculateBusinessInsights(items)`：纯数据函数。复用 `rankProducts` 校验原始名称、整数分金额和数量，重算销售额与利润；调用 `summarize` 和 `safePercent` 计算总利润及整体利润率。返回并列最高商品、低于 20% 的商品、零销售额商品、无效记录数量及累计溢出状态。不修改源数组和存档。
- `generateBusinessAdvice(data)`：纯规则函数。按空列表、无效数据、零收入、亏损、利润率不足或达标等条件返回中文建议数组；对低利润率名单及最高利润商品给出条件式建议，避免把销量或未来需求当作已知事实。
- `renderBusinessInsights()`：展示函数。把计算与建议结果填入新增模块，使用 textContent 显示商品名称和建议，避免 HTML 注入。由现有 render() 调用，所以添加、保存修改、删除和页面恢复后都会更新。

### 边界规则

- 整体利润率 = 总利润 ÷ 总销售额 × 100%，不平均单品利润率。
- 利润率严格低于 20% 才提醒，判断使用未四舍五入的值。
- 总利润相同的最高商品全部显示，保持明细顺序；名称附明细序号区分同名记录。
- 零销售额的利润率为“—”，单独提示，不当作低利润率。
- 空列表显示总利润 0、利润率“—”和添加数据引导。
- 数据函数遇到无效记录时剔除并报告统计范围；累计溢出时不输出经营结论。主应用原有输入校验和存档校验仍保留。
- 全部商品亏损时，“总利润最高”仅表示亏损最少，建议会明确说明。
